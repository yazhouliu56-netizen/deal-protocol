## 二、交互范式（核心）

### 范式 1：对话式需求（LLM 主战场）
```
用户：周日下午想找人打羽毛球
  ↓ 引擎追问链（按缺失维度逐条追问）
  · 水平段位？（新手/业余/进阶）
  · 哪个区域？（五公里内 / 指定区域）
  · 预算？（单次 50 以内等）
  · 几个人？（2 人单打 / 4 人双打）
  ↓ 全部就绪 → 生成提案（范式 2）
```

### 范式 2：生成式 UI（对话流内嵌可交互卡片）
- **时间槽卡**：可用时段横滑选择，点击即选
- **服务者卡**：摄影师/球友/师傅卡（头像/评分/价格），点击进详情
- **价格对比卡**：同品类多方案并排
- **确认单卡**：AI 汇总需求 + 所选方案 → 一键预订
- 卡片即聊即点，不跳出对话（点"预订"才进订单）

### 范式 3：智能体协调（演示亮点：球局撮合）
- 多轮对话中引擎自动做：多方日程协调（提案"周六 15:00 或周日 14:00 哪个行？"）、人数补齐提示（"再找 1 人就是双打了，要帮你发约局吗"）

### 可插拔对话引擎（架构接口）
```ts
interface ChatEngine {
  send(userMessage: string): AsyncIterable<ChatEvent>; // 流式事件
}
type ChatEvent =
  | { type: "text"; content: string }          // 追问/回复
  | { type: "card"; card: GenCard }            // 生成式卡片
  | { type: "typing" }                         // 思考态
  | { type: "done" };
// MockEngine：本地规则引擎（本轮）
// LLMEngine：真 API 适配器（后续一行配置切换）
```

## 五、开发顺序（里程碑）

- **M1 对话引擎**：ChatEngine 接口 + MockEngine + 对话屏 UI（多轮追问、流式打字、思考态）
- **M2 生成式卡片**：时间槽/服务者/对比/确认单卡 + 点卡预订 → 订单闭环
- **M3 订单闭环**：订单列表/详情/评价 + 个人中心 + Home 改造（对话条 + 品类入口）
- **M4 AR 接入 + 回归**：预订流进 AR 预览 + 行程联动 + 全尺寸回归
