> 目的：给「开放局/拼位 + P2P 信号波撮合 + P8 候选」提供系统化竞品参照。

> 原则：不只抄玩法，更关注海外平台**如何从用户视角打磨信任·定价·爽约**。

## 一、全景骨架（5 个维度 × 每平台 3 格）

## 二、①开放局/拼位 深入 — 我们缺什么

对照 Playtomic + BlaBlaCar + Meetup，逐条查缺口：

### 已有 ✅
- 拼位占座（joined → accepted，满员成局）+ 需求方提前成局
- 人均计价（budget ÷ capacity）
- 鸽子险按位冻结（爽约赔付）
- 评价/信用/治理全链路复用

### 缺口 ⚠️（按优先级）

| # | 缺口 | 对标来源 | 建议 |
|---|------|---------|------|
| 1 | **成团失败退款/补偿** | Playtomic 自动取消退款 | 拼不满到期：已拼位者押金自动退回 + 平台提示"转普通单/重发"；需求方预算不被占用 |
| 2 | **开放期取消梯度** | BlaBlaCar 24h 阶梯 / Playtomic 24h | 成局前自由退（已有）；成局后按 24h 阶梯：≥24h 全额退、<24h 扣鸽子险、临场全扣 |
| 3 | **No-show 欠款锁定使用** | Playtomic | no-show 者欠款未还清前不能发波/拼位（比封禁轻，更易落地） |
| 4 | 组局者身份/订阅层 | Meetup | 高频发起开放局的用户给"组织者"徽章 + 活动管理权益 |
| 5 | 拼位邀请裂变 | 拼多多 | "差 2 人成局"生成邀请卡/链接，PWA share |
| 6 | 等级/水平匹配 Request a spot | Playtomic | 羽毛球局可加"水平段位"，不符者可申请等全员批准 |

### 结论
缺口 #1 #2 #3 是三件事闭环必需的（信任底线），#4 #5 是增长，#6 是进阶。建议：**下个迭代先落地 #1+#2+#3**（成团失败退款 · 24h 阶梯取消 · no-show 欠款锁定）。

## 三、②P8 三方向 快速对标

### P8-A 账号体系 + 身份漫游
| 对标 | 做法 | 启示 |
|------|------|------|
| **TaskRabbit** | 强制身份验证（Persona 合规）；只允许注册本人接单（防顶替） | 我们的双 tab 身份是"匿名 P2P"，P8 账号化后要保留"身份漫游"（一个账号多设备）但**禁止顶替代做** |
| **Airtasker / Playtomic** | 成就/等级跨设备同步 | 账号化是信任记账的前提：评价/信用/欠款都挂账号不挂 tab |

### P8-B PWA 真通知
| 对标 | 做法 | 启示 |
|------|------|------|
| **Thumbtack** | 响应速度决定赢单（78% 找第一个响应者）| **推送通知 = 撮合转化第一杠杆**，远超"虚拟拨号" |
| **BlaBlaCar** | Booking request 通知 → 司机手动批准（70% 手动审查）| 拼位请求通知 + "全员批准"流程需要真通知支撑 |
| **Meetup** | RSVP/活动提醒 | 已拼位者临场提醒（防 no-show）就靠通知 |

### P8-C 公开竞价市场
| 对标 | 玩法 | 启示 |
|------|------|------|
| **Airtasker**（主范本） | 发任务 → 多人出价赋单 → 担保付定金托管 → 完成放款（已抄：requestPayment 放款闸）| 我们把"先到先得接单"升级为"多人报价需求方选"；已具备 offer/磋商机制 |
| **Thumbtack** | 4-5 个 pros 比价，pay-per-lead；78% 选第一个响应 | ⚠️ **竞价模式的代价是"响应速度 > 报价质量"**；且 pay-per-lead 模式我们不适合（无流量税可收）|
| 差距 | Airtasker 有 escrow 托管真实资金 + 保险（Chubb） | 我们要么虚拟流水演示，要么接支付（supabase 已就位）|

### 结论
- **A 账号 + B 真通知**是互相绑定的（通知要发到"账号的设备"，不是 tab），可捆绑做。
- **C 公开竞价**是产品模型切换（先到先得 → 多方竞价），建议放最后，且商业模式参考 Airtasker（佣金/服务费）而非 Thumbtack（卖线索）。

## 四、一句话总结

1. **开放局**机制已到位，但**成团失败退款 + 24h 阶梯取消 + no-show 欠款锁定**是信任闭环三口，必修。
2. **P8 路线**：账号漫游 + PWA 真通知捆绑上（通知是撮合转化第一杠杆）；公开竞价最后做，商业模式学 Airtasker 学佣金、不学 Thumbtack 卖线索。
3. **别抄**：Groupon 低价团购路线、Thumbtack pay-per-lead、闪送标准化履约——三条都不适合我们。

## 五、Meetup 专项对标（2026-08-13 实地调研）

> 资料来源：Meetup 官方 Help Center（RSVP/签到/等候名单/成员审批/Meetup+/群组政策）+ 官方 Blog（2026 路线图/16 项改进）。逐维度对照我们的已实现事实。

### 5.1 Meetup 机制全貌 → 我方现状对照

| 维度 | Meetup 机制 | 我方现状 | 差距等级 |
|------|------------|---------|---------|
| 参与门槛 | **群组级 Request to join 审批**：organizer 设置问题清单（profile questions），申请者作答，organizer 逐一批准；可 ban 成员 | 开放局拼位是**自动加入**（joined→accepted）；无 organizer 审批层 | 🟡 缺「组织者把关层」 |
| RSVP | 事件级 RSVP + **event questions**（报名时作答，leader 可见）+ **guest 携带**（默认 5 人上限，organizer 可调至 99） | 拼位即占位；无报名问卷、无 guest 携带 | 🟡 缺「报名信息采集 + 携伴」 |
| 名额/等候 | **attendee limit + waitlist**（满员进候补，**Meetup+ 优先补位**） | 满员即止，无候补名单 | 🟡 缺「候补转正」 |
| 到场核验 | **Check-in 签到**（开场前 1h → 活动中 → 后 24h；QR 码签到 2026 新增；Checked in/Not checked/No show/Not coming 四态） | **signInsure 签章 + fulfilment 履约验收**（更强：双向签章 + 保险壳 + 争议赔付） | 🟢 我方更强 |
| 缺席治理 | No show / Not coming 标记 + **成员出勤历史档案**（Yes/No/waitlist/no-show 统计，organizer 视角） | **鸽子险押金 + no-show 违约欠款 + 信用分降级**（更强）；缺「organizer 视角出勤档案视图」 | 🟢 我方更强；缺出勤档案 UI |
| 评价 | **公开群组评分**（prospective member 可见）+ organizer 可回复单条评论 + **低分（≤3 星）强制写原因** | review + starRank + 信用分，双向评价 | 🟢 我方更强；低分强制解释可借鉴 |
| 反欺诈 | **群组审核制**（创建需 24h 平台审核）+ 禁止虚增成员/RSVP 数 + banned member 隐私剥夺 | **Sentinel 四路信号反欺诈 + roam 多开检测 + moderation 违禁词**（更强） | 🟢 我方更强 |
| 匹配即时性 | 静态搜索 + 兴趣标签 + 地理位置推荐；**主要面向预先组织的活动，即时性差**（用户评价的短板） | **match.ts 六维打分 + AI 撮合对话 + 信号波即时广播**（差异化核心） | 🟢 我方核心优势 |
| 商业化 | **organizer 订阅（Starter/Standard/Pro）+ Meetup+ 会员订阅**（免付费活动服务费/无限直发/候补优先/完整成员名单）+ 付费活动服务费 + 群 dues | P8 竞价佣金 + organizer 订阅层（OrganizerBoostCard 已建）+ 发布费 | 🟢 大体对齐；无「会员订阅免服务费」玩法 |
| 隐私合规 | 无未成年分级、无免打扰、无隐私号（美国平台，合规弱） | **ageGate 分级 + quietHours 免打扰 + privacyNumber 隐私号 + guardianConsent**（《未保条例》对齐） | 🟢 我方合规差异化 |
| 成员触达 | Meetup+ 解锁「unrestricted DM」；免费用户仅能回复 | 我们 IM 私信线程免费开放（privacyNumber 隐私号包裹） | 🟡 我方无 DM 付费墙（宪法 #10 降级设计：通讯是基建不锁） |
| 通知 | 活动提醒/RSVP 通知 | PWA 真通知（未上线，P8-B）+ 本地系统通知 + quietHours 免打扰 | 🟡 待 P8-B 真推 |

### 5.2 对标结论（吸收 5 项 / 3 项裁决记录）

**✅ 吸收（已确认进 backlog，2026-08-13 用户裁决）**：
1. **组织者把关层（Request to spot）**——对应竞品矩阵 §2 缺口 #6（Playtomic Request a spot）+ Meetup 成员审批：给「开放局」加可选的「发起人审批制」开关（默认自动，高级局可开审批），复用 judge/fulfilment 治理。★优先 ✅ **已落地 ADR-0017**（wave.ts needApproval/joinRequests + requestSeat/approveRequest/rejectRequest + store decideRequest + WaveCard/WaveFeed/MyWaves/PublishSheet UI，+5 单测 387 全绿）
2. **waitlist 候补转正**——满员后进候补，有人退出按顺序/按信用分补位，配合现有 release 机制。
3. **低分强制解释**——review 打 ≤3 星必须填理由（防恶意差评 + 提信息量），改动小。
4. **organizer 出勤档案**——复用现有 no-show/violation 数据，补一个「发起人看本局成员出勤史」视图。
5. **guest 携带 +1**——开放局允许发起人设「可携伴人数」，注意：**携伴者需实名登记**（合规对齐 ageGate/privacyNumber）。

**记录在案（用户逐条裁决，2026-08-13）**：
- 🟦 **Meetup+ 付费解锁通讯/成员名单 = ⏸️ 现阶段不上 · 潜在赢利点**——用户定调：不立即做，但**记录为未来盈利点**；若以后启用，属「通讯/名单的付费通道」，届时走宪法 §3 冲突上报，由用户拍板接受偏离后才会放开。当前倾向：付费解锁**不碰通讯基建**（宪法 #10），可能的形态是「完整成员名单/高级触达」这类增值查看。
- 🟦 **群 dues（组织者向成员收会费） = 🚫 C 端不抄 · 归 B 端场景**——用户定调：这更接近「场地商家或商家销售」干的事（B 端/场地侧角色），不属于 C2C 组局者职责；我们不向 C 端成员收 dues，组织者收费走 P8 组织者订阅。
- 🟦 **静态兴趣搜索 = 🚫 落后不抄**——用户定调：本质上接近「微信群」模式（慢、滞后、无即时匹配），与我们 match.ts 即时撮合路线直接冲突，不做「兴趣广场」。

### 5.3 一句话
Meetup 在**组织者运营 + 报名漏斗（RSVP 问卷/候补/审批）**上比我们完善，但其**签到/缺席治理/反欺诈/匹配即时性/合规**全部弱于我们已实现的 fulfilment + Sentinel + match.ts + ageGate 组合——已确认吸收 5 项（审批/候补/低分解释/出勤档案/+1 携伴）补「玩法全→运营全」；3 项裁决记录：付费解锁暂不上（潜在赢利点）、群 dues 归 B 端不抄、静态搜索落后不抄。
