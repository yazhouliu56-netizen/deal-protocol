# 设计宪法（DESIGN CONSTITUTION）

> **最高指导思想**：本仓库（deal-protocol：web / mobile / 共享后端）的所有设计与评审，
> 以本文条文为默认准绳。任何与本文冲突的设计选择，不得静默通过——必须按「冲突上报」
> 流程交给用户裁决（见 §3）。

**元宪法（Meta-Constitution）声明（2026-08-15 人类创始人下达）**：
全项目唯一真理源 = **RPG 火箭筒微内核模型**——四层架构
（①40mm 通用发射筒底座层 / ②超口径多元弹药层 / ③火控雷达 AI 中枢层 / ④六层防御圈）
与 **6 大工程防腐红线**（隔离墙 / 声明式弹药 DSL / 单向依赖流动 / 零信任物理感知 /
弹道惯性降级 / 前端视界投影隔离）。
本宪法所有条文均为该元宪法的工程投影；任何设计、重构与代码生成必须无条件服从。
四层定义、六红线全文、全仓资产归属映射表与落差清单：**`docs/ARCHITECTURE_TAXONOMY.md`**（白皮书 = 架构归属唯一事实来源）。

全项目模块编号唯一标准 = 六层防御圈 × 核心模块职责矩阵，编号 `L1-M1`～`L6-M4`

引用该编号；新增模块一律走宪法 §3 上报流程，由人类裁决后登记进白皮书 §三 3.4。

**前端交互工程红线（2026-08-15 人类创始人注入）**：

   位置与层级；
2. **禁止品类硬编码全套页面**——严禁为单一品类硬编码独立全套页面与布局，
   一切业务必须以弹药形式（`IAmmoDefinition` + JSON-Schema）经动态视口装载渲染。

## §1 宪法条文（可裁定的短句规则）

| # | 条文 | 可裁定判据（违规即触发上报） |
|---|------|------------------------------|
| 1 | **底座优先**：任何新功能先定位到六层防御圈（①触达 ②业务核心 ③AI 神经 ④生态网关 ⑤安全风控 ⑥生存基建）；定位不进底座的，即为弹药，必须走弹药通道 | 设计评审无「六圈定位声明」 |
| 2 | **接口保守、火力激进**：发射管接口（订单状态机枚举、ledger 分录、信用评级、IM 协议）语义一经定义，只可增补、不可改义 | 新增业务要求改动既有状态机/分录语义而非新增 |
| 3 | **先配表后写码**：计价公式、分发权重、风控引信、动态表单四张弹药表无该业务配置项时，该业务不允许写代码 | 新业务代码先于 ammo 表配置合入 |
| 4 | **弹药可插拔**：新业务不得在组件/页面/引擎里写死业务字段（价格单位、SOP、门槛词）；一切业务参数经 `src/ammo/` 表驱动 | 出现写死业务字段的常量/分支 |
| 5 | **引信跟弹药走**：风控策略随弹药配置切换（押金/录音/视频验真/进家门槛勾选即生效），底座不为单一业务写死风控 | 风控逻辑写在 base 却无弹药表开关 |
| 6 | **信任数据是瞄准镜**：信用评分（守时/专业/礼貌等维度）+ 履约记录沉淀优先于一切增长功能；弹药可换，信用资产跨弹药累积 | 新弹药无信用数据接入点 |
| 7 | **LLM 能介入就介入**：需求解析、匹配推荐、争议定责、审核、BI 等环节默认评估 LLM 接入；不接入须在设计文档记录理由 | 设计缺「LLM 介入点评估」记录 |
| 8 | **隐私是血液规则**：全生命周期脱敏（分级脱敏/虚拟 ID/阅后即焚/遗忘权）是所有模块的共同约束，不是某个独立模块 | 新接口传输/存储真实手机号、门牌、票据明文 |
| 9 | **先问旅程再写界面**：任何用户侧功能先定义「玩家旅程」（角色 → 能力 → 成长感 → 复访钩子），再谈界面与交互 | 设计只有界面稿、无角色/成长定义 |
| 10 | **降级是设计的一部分**：弱网、断供（地图/支付/LLM）、过载都必须有显式降级路径，不允许「唯一依赖某个外部/单一通道」 | 系统图存在无 fallback 的单点依赖 |

## §2 覆盖范围与效力

- 本文管「为什么设计」（意图层），是**最高权重**；项目工程事实（构建命令、目录、
  代码风格）管「怎么落地」（执行层），两者冲突时按 §3 上报，由用户裁决。
- 已有代码与本文不符的（历史遗留）：不算违规，但**每个结构性改动（重构/抽层）**
  必须顺带收敛一处，在改动说明中标注「宪法收敛：条文 #n」。
- ADR-0006 的六层防御圈是本文的架构投影；后续 ADR 必须显式声明「派生自宪法 #n」。
- 新 ADR / 新功能设计文档强制含两栏：**「六圈定位声明」+「宪法条文对照」**
  （模板见 §4）；缺失即退回补写。

## §3 冲突上报流程（用户拍板，禁止静默）

1. 设计过程中发现与某条文相悖的需求/选择时，**不得自动拒绝，也不得自动放行**；
2. 将该条写成「⚠️ 宪法冲突上报」记录：相悖条文 #n + 需求上下文 + 拟选方案 +
   权衡说明；
3. 交给用户拍板（接受偏离 / 拒绝 / 调整方案），裁决结论写回设计文档留痕；
4. 用户拍板接受的偏离 = 本次有效裁决，不改变宪法本身；同样的冲突再次出现仍须
   再次上报，不自动沿用上次裁决。

## §6 PMF 探索期日落特区条约（Pre-PMF Sunset Protocol）

> **效力声明（Supremacy Clause）**：本条约经用户裁决授权生效。在特区存续期间，
> 涉及增长验证与 PMF 探索的开发活动，其执行效力高于正文 §1 第 1-10 条通用条款；
> 正文条款未被本条约明确替代或豁免的部分仍具完全约束力。
> **例外**：#8 隐私血液与 V4 资金安全（反二清）为不可豁免红线，不在效力让渡范围内；
> 本条约不改变元宪法四层架构与六红线的真理源地位，仅为探索期执行特例。

### §6.1 增长特区 `src/app/(growth)/**` 与外骨骼豁免

为极速获取真实用户、验证商业模式，设立物理隔离区 `src/app/(growth)/**`：

1. **页面实现自由**：
   - 允许为特定品类、投放活动硬编码全套落地页与转化漏斗；
   - 允许绕过 `IAmmoDefinition` 弹药视口与动态分发逻辑；
   - 允许穿透或定制外骨骼锚点布局（不强制遵循固定插槽约束）。
2. **不可突破之红线（零豁免）**：
   特区绝非法外之地，以下两条具有最高不可侵犯性，违背即触发 §3 上报：
   - **#8 隐私血液底线**：严禁明文呈现、存储或传输用户真实手机号、详细门牌地址、
     身份证件、非脱敏支付账单；
   - **V4 资金安全与反二清底线**：严禁绕过 `src/base/money/escrow.ts` 与平台托管状态机，
     直连任何第三方收付款逻辑。

### §6.2 协议重构与数据清算（Clean Slate 轨）

在无真实用户资金沉淀阶段，杜绝向下兼容代码债务：

1. **允许破坏性改义**：
   核心领域契约（含状态机语义、订单流转、枚举定义）允许按市场认知直接破坏性重构；
   严禁引入 `v1 -> v2` 适配器或双写兼容层；重构后保持单版本干净。
2. **数据库硬护栏（二选一，严禁无声删字段）**：
   涉及 `src/base/order/wave.ts` 或 `supabase/migrations/**` 结构变更时，
   提交必须显式满足以下之一：
   - **方案 A（连续迁移）**：附带对应字段删除 / 表重构的破坏性迁移 SQL；
   - **方案 B（数据抹平重置）**：提交说明显式声明 `[DB-RESET: APPROVED - NO REAL USERS]`，
     经用户确认后执行全量数据库重置。

### §6.3 核心条文的特区替代执行规则

特区存续期间，正文第 3、6、7 条按以下规则替代执行：

1. **#3 先配表后写码 -> 替代为「三次原则（Rule of Three）」**：
   - 品类 1：允许完全硬编码落地页与流转逻辑，快速验证商业闭环；
   - 品类 2：允许复制微调，快速验证跨品类泛化度；
   - 品类 3 出现时：强制收编抽象，提炼为 `IAmmoDefinition` 并注册至弹药注册表。
2. **#6 信任优先 -> 替代为「摩擦预算（Friction Budget）」**：
   信用沉淀随增长复利，严禁前置阻碍转化；任何新增安全验证、资质审核、多步确认环节，
   须证明其"打消疑虑转化增量"大于"跳出率损耗"；未经实证前，非资金核心链路的安全保障
   默认采用异步后置处理。
3. **#7 LLM 能介入就介入 -> 替代为「成本与延迟护栏（Cost and SLA Guardrails）」**：
   核心交易主链路（发单、计价、撮合、支付状态推进）必须为确定性纯代码、毫秒级响应；
   LLM 仅限旁路场景（意图容错、辅助录入、争议长文本摘要）；凡接入 LLM 处必须标注
   Token 成本上限与超时降级：交互阻塞链 1.5s 内降级，非阻塞旁路放宽至 8s。

### §6.4 特区门禁调度规则（物理校准）

Next.js App Router 存在 tsc 通过但构建失败的真实风险，特区门禁如下：

1. **`src/app/(growth)/**` 变更门禁**：
   - 必跑：`tsc --noEmit` + `lint:changed` + `npm run build`；
   - 本地单测仅跑变更关联的 Affected Tests；全量单测（以 `docs/PROJECT_STATUS.md` 基线为准）
     委托 pre-push 统一执行；
   - 豁免：`verify-scoped` 端到端集成测试、DoD 缺陷考卷复利条款、`CONVERGENCE-LOG.md` 登记。
2. **机治脱节防护**：门禁脚本（`detect-tier.mjs` / `e2e-map.mjs` / `convergence-check.mjs`）
   适配 `src/app/(growth)/**` 特区规则前，本节豁免条款人工执行，不得视为自动生效。

### §6.5 分级退出信号与日落机制（Two-Stage Sunset）

特区非永久制度，按商业指标分级退出：

1. **阶段一：核心协议轨冻结**
   - 触发条件：平台累计完成 **100 笔非熟人真实交易**。
   - 统计口径（V1，基于现有 `orders` 表字段；`buyer_id / seller_id / device_fingerprint / internal_testers`
     当前不存在，不可写入口径）：
     ```sql
     SELECT COUNT(*) FROM orders
     WHERE status = 'SETTLED'
       AND provider_id IS NOT NULL
       AND user_id <> provider_id
       AND user_id NOT IN (<内部测试白名单 user_id 列表>);
     ```
     V2 TODO：设备指纹去重与 `internal_testers` 表建成后补入排除逻辑。
   - 日落动作：核心状态机与协议语义即刻冻结；此后底层改动恢复正文 #2 全量效力
    （只增不改义、标准迁移脚本、收敛表登记）。
2. **阶段二：增长特区收编**
   - 触发条件：连续 4 周 WAU > 1000，且 30 天留存达基线（初值 >= 20%，届时按品类复核修订）。
   - 统计口径（V1，客户端埋点缺失前）：`orders` 表滚动 7 天去重 `(user_id + provider_id)`；
     埋点建成后切换为有效交互行为去重 `user_id`。
   - 日落动作：召开复核会议；对 `src/app/(growth)/**` 清算——优胜硬编码页按三次原则
     提炼为弹药与正式路由，落选页彻底下线删除；本 §6 宣告废止，全仓回归正文全量治理。
