# 设计宪法（DESIGN CONSTITUTION）

> **最高指导思想**：本仓库（deal-protocol：web / mobile / 共享后端）的所有设计与评审，
> 以本文条文为默认准绳。任何与本文冲突的设计选择，不得静默通过——必须按「冲突上报」
> 流程交给用户裁决（见 §3）。

**哲学出处**：RPG 火箭筒设计哲学 → O2O 平台迁移（2026-08-08 网聊定稿，全文
`RPG设计哲学与生命力.md`）。一句话定义：
**平台 = 「万能底座（人到人的信任与交付基建）」 + 「可插拔弹药（场景 SOP）」——
用最笨的物理接口标准，锁死最聪明的进化；底座保证"扣动扳机那一刻"的确定性。**

**派生文档**：ADR-0006（六层防御圈蓝图 = 宪法的架构投影）→ ADR-0007（base/ammo 落地 =
宪法第一轮执行）。

## §1 宪法条文（可裁定的短句规则）

| # | 条文 | 可裁定判据（违规即触发上报） |
|---|------|------------------------------|
| 1 | **底座优先**：任何新功能先定位到六层防御圈（①触达 ②业务核心 ③AI 神经 ④生态网关 ⑤安全风控 ⑥生存基建）；定位不进底座的，即为弹药，必须走弹药通道 | 设计评审无「六圈定位声明」 |
| 2 | **接口保守、火力激进**：发射管接口（订单状态机枚举、ledger 分录、信用评级、IM 协议）语义一经定义，只可增补、不可改义 | 新增业务要求改动既有状态机/分录语义而非新增 |
| 3 | **先配表后写码**：计价公式、分发权重、风控引信、动态表单四张弹药表无该业务配置项时，该业务不允许写代码 | 新业务代码先于 ammo 表配置合入 |
| 4 | **弹药可插拔**：新业务不得在组件/页面/引擎里写死业务字段（价格单位、SOP、门槛词）；一切业务参数经 `src/ammo/` 表驱动 | 出现写死业务字段的常量/分支 |
| 5 | **引信跟弹药走**：风控策略随弹药配置切换（押金/录音/视频验真/进家门槛勾选即生效），底座不为单一业务写死风控 | 风控逻辑写在 base 却无弹药表开关 |
| 6 | **信任数据是瞄准镜**：信用评分（守时/专业/礼貌等维度）+ 履约记录沉淀优先于一切增长功能；弹药可换，信用资产跨弹药累积 | 新弹药无信用数据接入点 |
| 7 | **LLM 能介入就介入**：需求解析、匹配推荐、争议定责、审核、BI 等环节默认评估 LLM 接入；不接入须在设计文档记录理由 | 设计缺「LLM 介入点评估」记录 |
| 8 | **隐私是血液规则**：全生命周期脱敏（分级脱敏/虚拟 ID/阅后即焚/遗忘权）是所有模块的共同约束，不是某个独立模块 | 新接口传输/存储真实手机号、门牌、票据明文 |
| 9 | **先问旅程再写界面**：任何用户侧功能先定义「玩家旅程」（角色 → 能力 → 成长感 → 复访钩子），再谈界面与交互 | 设计只有界面稿、无角色/成长定义 |
| 10 | **降级是设计的一部分**：弱网、断供（地图/支付/LLM）、过载都必须有显式降级路径，不允许「唯一依赖某个外部/单一通道」 | 系统图存在无 fallback 的单点依赖 |

## §2 覆盖范围与效力

- 本文管「为什么设计」（意图层），是**最高权重**；项目工程事实（构建命令、目录、
  代码风格）管「怎么落地」（执行层），两者冲突时按 §3 上报，由用户裁决。
- 已有代码与本文不符的（历史遗留）：不算违规，但**每个结构性改动（重构/抽层）**
  必须顺带收敛一处，在改动说明中标注「宪法收敛：条文 #n」。
- ADR-0006 的六层防御圈是本文的架构投影；后续 ADR 必须显式声明「派生自宪法 #n」。
- 新 ADR / 新功能设计文档强制含两栏：**「六圈定位声明」+「宪法条文对照」**
  （模板见 §4）；缺失即退回补写。

---

## §3 冲突上报流程（用户拍板，禁止静默）

1. 设计过程中发现与某条文相悖的需求/选择时，**不得自动拒绝，也不得自动放行**；
2. 将该条写成「⚠️ 宪法冲突上报」记录：相悖条文 #n + 需求上下文 + 拟选方案 +
   权衡说明；
3. 交给用户拍板（接受偏离 / 拒绝 / 调整方案），裁决结论写回设计文档留痕；
4. 用户拍板接受的偏离 = 本次有效裁决，不改变宪法本身；同样的冲突再次出现仍须
   再次上报，不自动沿用上次裁决。

## §4 ADR / 功能设计模板（强制字段）

```markdown
## 六圈定位声明
- 所属圈：第 _ 圈（触达/业务核心/AI神经/生态网关/安全风控/生存基建）
- 所属模块：_（对应圈内模块名）
- 复用底座：base/_ 的哪些引擎（状态机/清结算/信用/IM/网关…）
- 弹药表：需要新增/修改 ammo/_ 的哪些配置（无则不填）

## 宪法条文对照
- 命中条文：#_（一句话说明如何符合）
- 偏离条文：#_（须走 §3 冲突上报，未裁决不得合入）
```
