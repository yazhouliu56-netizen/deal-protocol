# ADR-0021: 争议处置「LLM 仲裁建议书 + 分级签发」（EASY/MEDIUM/HARD）

日期：2026-09-12
状态：Accepted（2026-09-12 落地：policy 纯核＋resolver 接线＋housekeeping/appliance_repair 弹药配置；门禁 T2 全绿）

## Context

ADR-0008 立了"小法官只出建议、人工确认"，并把自动执行留给后续 ADR——本 ADR 即该续篇。背景压力三方齐至：① 315 后行业共识"定价/定责权收归系统"；② 电商法 61/63＋人民法院案例库（2024-08-2-137-005）明确平台在"协议预置＋凭证齐全＋商家怠于处理"三前提下可扣划先行赔付，缺一即违法；③ 上海市场监管指引要求保证金用途明确＋申诉复核通道，饿了么"小饿评审团"验证大众评审提申诉通过率 18%。

本地骨架已在：`arbitrate()` 按金额分档（EASY≤200/MEDIUM≤2000/HARD 强制人工），`canAutoExecute()` 以 0.85 置信度定自动生效；moderation 已验证"机器初筛＋人工终裁＋审计＋撤销窗"治理形状。本 ADR 只做收编与补齐，不另起炉灶。

## Decision

### 一、建议书形态（LLM 的法定输出上限）
- `ArbitrationVerdict` 即《仲裁建议书》：结论＋置信度＋证据引用（链上环号/帧号，防编证据）＋适用条款（弹药 arbitration 配置项）。LLM 不得输出划扣指令。
- 引用证据须经 evidence-chain 哈希校验；校验失败该条引用作废并降置信度。

### 二、三档签发
- **EASY**（小额＋置信度 ≥ 自动线）：自动生效，执行仍走 escrow 状态机，全程审计可回滚。
- **MEDIUM**：议会仲裁（`council-arbitrator` 已有）或人工复核；预留"用户评审团"扩展位（对标小饿评审团）。
- **HARD**：强制人工（现状 `throw` 保持，补人工仲裁工作台入口）。
- 自动线（金额＋置信度）按品类进弹药配置，默认沿用 200/2000 与 0.85。

### 三、先行赔付三前提（代码级门禁，缺一不可）
1. 协议预置：发单/接单时已勾选含扣划授权的争议条款（无勾选记录 → 拒绝先行赔付，只走普通仲裁）；
2. 凭证齐全：开工/完工影像＋在户时长三件套缺一 → 不降档、不自动；
3. 商家举证窗：对标 48h 举证，超时未举证判不利；商家已举证一律转人工/MEDIUM。
- 申诉窗：终裁后双方可申诉一次（复用 moderation withdrawn/重报语义形状），申诉期资金冻结不划转。

### 四、隐私前置（#8 不可豁免）
- 音频等连续取证须 consent＋最小必要＋ 30/180 天清理（复用 privacy-erasure）；调阅留痕；对外文书一律脱敏。

## Alternatives Rejected

- **LLM 3 秒自动划扣**：误判即供给侧流失（平台自杀按钮）；且违反 V4（绕过 escrow）与三前提，否决。
- **纯人工仲裁**：与 #7 相悖，且长尾成本打不下来；EASY 档自动化是必选项。
- **平台单方终裁无申诉**：违反上海指引申诉复核要求＋电商法公平原则，否决。

## Consequences

- 新增/修改：`ammo/<品类>` arbitration 配置（首批：housekeeping/appliance_repair）、签发执行与 escrow 对接、申诉窗状态、建议书证据引用校验；`src/lib/arbitration` 阈值配置化（宪法收敛 #5）。
- 门禁：T2 ＋ 三前提门禁考卷（无协议勾选拒赔付/凭证缺失不降档/举证窗超时判不利）＋ 申诉窗考卷，全绿方可合入。
- 后续依赖：ADR-0019（确诊纠纷输入）、ADR-0020（试单纠纷输入）；人工仲裁工作台、用户评审团另起 ADR。
